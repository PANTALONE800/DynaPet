DynaPet v3.4.0 · Windows x64 使用指南

一、适用电脑与包内内容
本包为 Windows x64 版本，建议使用 Windows 11 x64；不是 macOS 或 Windows ARM64 原生包。
包含 DynaPet.exe、使用说明.txt、测试主题和许可／隐私声明。自带 .NET 运行时，无需另装 .NET SDK、Python 或 Node.js。

二、解压与第一次启动
1. 下载后右键 ZIP，选择“全部解压”，放到自己的固定目录。不要在压缩软件预览窗口中直接运行。
2. 先退出旧版，再在解压后的目录双击 DynaPet.exe。请保留整个包的结构和声明文件，不要只拖出一个 exe。
3. 桌宠出现后播放欢迎动作，再进入自动感知；右下角系统托盘提供入口，图标可能收在“显示隐藏的图标”区域。正常运行不会出现命令行控制台。
4. 此测试版没有 Authenticode 签名。若系统提示未知发布者或拦截，请先核对下载来源和 SHA256；若系统报告威胁或管理员策略禁止运行，应停止并查看详情。不要关闭 Defender、SmartScreen 或防火墙。
5. 以普通用户运行，无需“以管理员身份运行”。首次启动不会自动开启 OCR 或登录启动。

三、日常操作
• 单击桌宠可“摸摸”，按住鼠标左键拖动可移动位置。
• 右键桌宠打开菜单；桌宠被隐藏时，从菜单栏／系统托盘选择“显示桌宠”。隐藏不等于退出。
• “展开状态面板”可查看当前状态和环境信息；“收起状态面板”可减少占用。
• “动作预览”可手动查看动作；选“自动感知”返回自动状态。预览后长时间不变，先检查是否仍处于手动预览。
• “暂停动作”冻结动画；选择“恢复动作”继续播放。“大小”可选 75%、100%、125%。
• 原创几何圆点是默认演示角色，用于演示引擎，不是缺少角色文件。默认各心情的画面可能相似，可导入自己的动画主题。

四、先选择合适的导入方式
要做什么                         菜单入口与准备方式

不同状态使用不同静态图           “导入角色图片…”，一次选中 1～11 张图片；按第五节命名。
导入一个 GIF 动画                “导入角色图片…”，只选这一个 GIF；所有状态共用该动画。

下载的 ZIP 一律先完整解压。不要混合选中 GIF 与静态图片，也不要一次选中多个 GIF；多 GIF 使用带配置的主题包。

五、静态图片：命名、匹配和状态说明
5.1 单张图片
原始文件名可以自定，例如“我的角色.png”。导入后所有状态共用这张图片，但状态标题和说明仍会随应用规则变化。这不代表导入失败。

5.2 多张静态图片
一次选中准备好的图片，macOS 可按 Command 多选，Windows 可按 Ctrl 多选。也可以将它们放在同一目录，用“导入主题包…”选择该目录。
支持 PNG、JPG、JPEG、BMP；推荐有透明背景的 PNG。下面的 .png 可以换成支持的静态图片扩展名，但点号前的英文状态名要正确。建议使用小写，不添加编号、空格或“副本”等后缀。

文件名          对应状态标题／用途
welcome.png     欢迎回来：启动／唤醒欢迎
idle.png        陪着你：普通待机，也是缺图时的首选回退图片
focus.png       专注中：工作／文档等场景
happy.png       好耶：例如接通外接电源时的状态
hot.png         有点忙：系统较忙；不是实际温度测量值
dizzy.png       忙晕了：高负载状态
puzzled.png     在找什么呀：文件管理等场景
sleepy.png      困困：闲置或连续使用提醒
low.png         快没电啦：低电量提醒
shy.png         被摸摸了：点击／摸摸反应
message.png     macOS 为“有新动静”；Windows 为“惊喜”，只作手动预览

不必准备齐 11 张。某个状态没有对应图片时，优先使用 idle 图片；连 idle 也没有时，用导入时取到的第一张图片。两平台目录枚举顺序可能不同，不要依赖“第一张”来控制外观，建议总是准备 idle.png。
同一批图片不要有重复的状态名，例如 idle.png 与 idle.jpg；它们会争用同一个状态，不能用来制作多帧动画。
随意命名的多张图不会自动分配给不同状态。例如“开心.png”不会自动对应 happy；请改为 happy.png。happy_1.png 也不等同于 happy.png。
示例：只提供 idle.png、happy.png、shy.png 时，开心显示 happy，摸摸显示 shy，其余未提供的状态显示 idle。

5.3 图片名与文字是两件事
图片文件名只决定“这个状态用哪张图片”，不改状态标题、提示语、触发条件，也不新增状态。
例如把生气表情的图片命名为 happy.png，开心状态仍显示“好耶”，只是画面变成你提供的生气表情。
当前不提供通过主题自定义文案或新增状态的设置。主题 name 字段只是主题名称，不是桌宠说的话。
验证图片对应是否正确：导入后打开“动作预览”，逐个选择状态；看完选择“自动感知”回到日常模式。摸摸等短暂状态可能暂时覆盖预览，请稍等再看。

六、GIF 动态主题：从体验到自制
6.1 体验随包主题
1. 找到“测试主题/MinimalGif”，确认直接包含 theme.json 和 demo.gif。
2. 右键桌宠 →“导入主题包…”，选择 MinimalGif 文件夹本身；不要选外层“测试主题”，也不要选 theme.json 文件。
3. 应看到 8 帧圆点循环移动。示例的 idle、touch、sleep 都使用同一个 GIF，状态变化时外观相同是正常的。

6.2 制作多个状态的主题
建立“我的主题”文件夹，直接放入 theme.json、idle.gif、touch.gif、sleep.gif。用纯文本编辑器将以下内容保存为 UTF-8 的 theme.json：
{
  "format": "dynapet-theme",
  "version": 1,
  "name": "我的桌宠",
  "states": {
    "idle": "idle.gif",
    "touch": "touch.gif",
    "sleep": "sleep.gif"
  }
}
检查文件真实扩展名，避免保存成 theme.json.txt。Windows 可在资源管理器“查看”相关选项中显示文件扩展名；Mac 可通过“显示简介”检查名称与扩展名。
三个必填键 idle、touch、sleep 不可省略，可以都指向同一个 demo.gif。JSON 使用英文双引号、冒号和逗号，最后一项后面不加逗号，不写注释。

6.3 GIF 文件名和状态键分别控制什么
状态键必须使用规定的英文名称；GIF 文件本身不必与状态同名。例如 "happy": "smile.gif" 表示开心时播放 smile.gif。只将文件改名为 happy.gif，不在 states 中配置，不会自动分配到开心状态。
必填：idle → 日常，touch → 摸摸（引擎 shy），sleep → 困困（引擎 sleepy）。
可选：welcome、focus、happy、hot、dizzy、puzzled、low、message。缺少这些可选映射时播放 idle。
注意：静态图用 shy.png 和 sleepy.png；GIF 配置用 touch 和 sleep，不能写成 shy 或 sleepy。未知状态键会被拒绝。
GIF 文件名必须满足：以英文字母或数字开头，主体共 1～64 个字符，仅含英文字母、数字、下划线和短横线，最后接小写 .gif。文件必须与 theme.json 同目录，引用大小写完全一致；不支持中文 GIF 文件名、网址、子目录、软链接或可执行插件。以上限制针对配置引用的 GIF；主题显示名称可用中文，name 长度为 1～128 个 UTF-8 字节。

6.4 大小与动画规则
• 单个 GIF 最大 32 MiB，画布每边 1～4096 像素，1～1000 帧；一个主题的不同 GIF 总大小不超过 64 MiB，解码画布像素总量不超过 6400 万。theme.json 最大 64 KiB。
• 解码像素量可按“宽×高×帧数”估算后将不同 GIF 相加；压缩体积小不一定占内存少。超限时应缩小画布或减少帧数。
• 按 GIF 自带帧时长和循环次数播放，不会自动把有限循环改成永久循环；有限动画结束会停在末帧。“暂停动作”会暂停，“恢复动作”会继续。动作切换、摸摸重播、导入或恢复主题会重新开始对应动画。
• 原图画布的留白会影响角色看起来的大小；优先准备尺寸与位置一致、透明背景适当的素材。不要期待应用自动逐帧裁剪对齐。
• 完整主题契约见源码 IPCDemo/SharedSpec/ThemePackageSpec.md；用户素材的使用与分享权限由其权利人决定。

七、换回旧主题、备份、修改与分享
7.1 换回以前导入的包
当前版本没有“历史主题列表”“上一个主题”或主题重命名界面，但旧主题副本会保留。
1. 右键桌宠 →“打开角色文件夹”。其中 theme- 开头的子文件夹是导入时生成的副本，不是易读的角色名称。
2. 打开各文件夹查看图片／GIF，结合修改时间确认想要的主题；不要根据随机编号猜测角色。
3. 回到桌宠菜单 →“导入主题包…”，选择这一份 theme-… 子文件夹本身，不要选外层 Themes。
4. 成功后切回该角色，同时生成一个新的导入副本。重复导入会增加副本，并不会覆盖旧包。
如果仍有原始主题包，也可重新导入原包；若只有原始散图，重新多选图片导入即可。
“恢复内置角色”只切回程序默认演示圆点，不删除旧主题，不会返回上一个主题。

7.2 原文件、导入副本与备份
导入会复制资源；导入成功后修改下载目录中的原图片，不会自动更新已选主题。修改后的主题应重新导入。
备份时复制整个主题子文件夹，包括 theme.json 和全部图片／GIF，放到应用目录以外并起一个易识别的外层文件夹名。只备份 theme.json 不够。
建议保留自制主题的原始图片和配置；静态图片导入副本已转换为内部用的 768×256 三帧条带，不是原始素材。不要把该条带当普通单张图片再导入，否则可能把三帧同时显示；应选择包含配置的整个主题目录。
不要直接修改或删除正在使用的副本。清理前先切到其他主题，退出应用，再备份并清理确认无用的副本；应用当前没有管理／删除主题的按钮。

7.3 分享和跨平台使用
将完整主题目录压成 ZIP，接收者先解压，再用“导入主题包…”选中含 theme.json 的目录。两平台使用相同 GIF 主题格式，不需要附带应用程序或可执行文件。
文件夹的外部名称可为方便管理而自定，但不要随意改包内资源名；GIF 改名后必须同步更新 theme.json。本机保存目录中的 theme-… 名称不要直接更改，避免当前选择失效。
只分享你有权再分发的素材。备份或分享前确认没有混入私人图片和无关文件。

八、Windows 手动 OCR 与隐私
Windows 版不提供消息监听、消息到达提醒或聊天软件状态；“message”仅用于手动动作预览。
1. 先切换到要识别的普通应用窗口，保持可见并等待片刻，让桌宠采样到前台窗口。
2. 右键桌宠，选择“识别前台窗口文字（本机 OCR）”。在确认框中检查窗口标题，确认目标正确后再继续。
3. 结果显示在本次文字识别窗口中；关闭结果窗口即可结束查看。应用不主动保存截图或识别正文。
4. 如果菜单不可用，先让一个有标题的非桌宠窗口成为前台窗口后再试。如果提示语言组件缺失，用“OCR 语言包设置”进入系统语言设置，按需安装对应语言组件。
5. 最小化、隐藏、受保护内容或权限不同的窗口可能无法捕获或识别；不要为此将桌宠改为管理员运行。恢复普通可见窗口再试。
OCR 仅由用户手动发起，在本机处理，不是后台持续读取聊天的功能；不需要时不发起即可。

九、登录启动、退出与更新
• 在固定目录运行后，可选择“开启登录时启动”；“打开系统启动应用设置”可查看系统管理入口。
• 要关闭自动启动，选择“关闭登录时启动”，并在系统启动应用设置检查状态。
• 隐藏桌宠仍会继续运行；完整退出请在右键或托盘菜单中选择“退出 DynaPet”。
• 更新前备份主题、关闭登录启动并退出旧版，将新包完整解压到新的固定目录，确认运行正常后再开启登录启动。移动／删除原目录会使旧的启动路径失效。

十、本机文件、重置与卸载
• 设置位于 %LOCALAPPDATA%/DynaPet/settings.json，导入主题位于 %LOCALAPPDATA%/DynaPet/Themes。可将 %LOCALAPPDATA%\DynaPet 粘贴到资源管理器地址栏访问。
• 想重置设置时，先退出应用，将 settings.json 改名为 settings.json.bak 后重新启动；位置、大小和主题选择会回到默认。原 Themes 文件夹不会因此删除，主题可重新导入。
• 卸载前先关闭登录启动、退出，再删除解压的程序文件夹即可。若也要清除本机设置与主题，请先备份，再删除 %LOCALAPPDATA%\DynaPet；无需手动编辑注册表。

十一、常见问题
• 找不到桌宠：从菜单栏／托盘选择“显示桌宠”，检查是否拖到了其他显示器。需要时退出后重新启动；不要反复启动多个实例。
• 导入主题失败：确认已解压、目录层级正确、三个必填状态齐全、GIF 文件名大小写一致、文件未损坏且未超限。先导入随包 MinimalGif，区分应用问题和主题问题。
• 动画不动：检查“暂停动作”状态；有限循环 GIF 正常结束会停在最后一帧。默认静态演示与自制 GIF 的动作丰富度取决于素材本身。
• 状态统计与实际不完全一致：部分数据按可见窗口和标题估算，不代表所有文档、标签页或聊天数量；权限和软件版本也会影响结果。
• 更新后异常：先退出全部旧版，再启动新包；保留自己的主题备份。不要把不同版本的文件混在一起。
• 反馈问题时，请在项目 GitHub Issues 提供系统版本、芯片／架构、应用版本、具体操作、预期与实际结果，以及是否使用自定义主题。截图先脱敏，不上传聊天内容、密钥或私人诊断信息。
